# خطة إصلاح وصول الرسائل والبلاغات إلى لوحة التحكم في AQURIVO

## المشكلة المحددة
1. **الاعتماد الكلي على Firebase Admin (`getAdminDb()`)**:
   - إذا لم تكن متغيرات بيئة `FIREBASE_ADMIN_*` مهيأة، تفشل عملية حفظ رسائل الاتصال ويتم تجاهل الخطأ بصمت (`skipped`), مما يوهم الزائر بإرسال الرسالة بينما لا تُحفظ في قاعدة البيانات وبالتالي لا تظهر في `/admin/messages`.
   - أما البلاغات (`/api/reports`) فتفشل وتعيد خطأ 500.

---

## خطوات الحل والتنفيذ

### 1. إضافة نظام تخزين احتياطي محلي (JSON File Fallback) لرسائل الاتصال والبلاغات
- تحديث `messages.repo.ts` و `reports.repo.ts` (أو إضافة مستودع احتياطي يعتمد على ملفات JSON المحلية ضمن مجلد `/server/data/`) لكي يتم حفظ الرسائل والبلاغات محلياً وسحابياً في آن واحد (أو محلياً كبديل تلقائي عند عدم توفر قاعدة بيانات Firebase السحابية).
- ضمان عرض جميع الرسائل والبلاغات المخزنة محلياً وسحابياً في لوحة تحكم الأدمن (`/admin/messages` و `/admin/reports`).

### 2. ضمان عدم ضياع أي رسالة
- تعديل `createContactMessage` و `createReportServer` لتسجيل الرسائل والبلاغات بضمان تام وعدم تجاهل أخطاء الاتصال بقاعدة البيانات.
- تحديث بريد إشعارات SMTP (`mailer.service.ts`) لضمان إرسال إشعار فور للبريد الإلكتروني للإدارة عند تلقي أي رسالة أو بلاغ جديد.
